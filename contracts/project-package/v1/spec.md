# Project Package v1

| Item | Value |
| --- | --- |
| Version | 1 |
| Status | draft (layout follows MVP 9.5; freeze pending review) |

| Freezes | week 6, by ticket J-01 (golden packages + `FROZEN`) |

| Schemas | `manifest`, `project`, `conversation`, `summaries`, `models` (`*.schema.json`) |

## 1 Purpose

The versioned ZIP format for exporting one project (with its conversations, messages and
summaries) and importing it into another AIOS store (MVP 9.5). Checksums detect damage; golden
packages in CI keep every later build able to import v1 packages.

## 2 Conventions

RFC 8785 JCS for every JSON file, UTF-8, no BOM; SHA-256 lowercase hex;
`H(tag, bytes) = SHA-256(UTF-8(tag) ‖ 0x00 ‖ bytes)`; RFC 3339 UTC time with milliseconds;
UUIDs lowercase.

**Unknown fields are kept** (MVP 9.5): a reader accepts fields it does not know on every object,
stores them with the item, and writes them back when the item is exported again. A reader never
drops data written by a newer build of the same package version.

## 3 Layout

```
manifest.json                          first entry, stored (no compression)
project.json
conversations/<conversation_id>.json   one per conversation, messages inline
summaries/<conversation_id>.json       that conversation's summaries (absent when none)
models.json                            catalogue references only, never model files
checksums.txt                          last entry
```

File extension `.aiosproj`. Entries other than `manifest.json` are deflated; names are sorted.
ZIP timestamps are fixed at 1980-01-01 00:00:00, so the same content gives the same bytes.

`checksums.txt` has one line per file except `manifest.json` and itself, sorted by path:
`<sha256 hex>  <path>\n` (two spaces, plain SHA-256 of the file bytes).
`manifest.checksums_sha256` is the SHA-256 of `checksums.txt`.

`manifest_digest = H("aios/project-package/v1/manifest", manifest.json bytes)`; it is recorded
in the `project_exported` / `project_imported` evidence events.

## 4 Contents

- `manifest.json`: `format` = `"aios-project-package"`, `v` (package version, 1),
  `package_id`, `created_at`, `app_version`, `schema_versions` (`{project, conversation,
  summaries, models}` → 1), `project_id`, `classification` (of the project), `counts`
  `{conversations, messages, summaries}`, `checksums_sha256`; optional `exporting_stream_id`
  and `export_event_id` (the evidence stream and event that recorded the export).
- `project.json`: `id`, `name`, `description` (nullable), `classification`,
  `classification_source`, `derived_from_project_id` (nullable), `created_at`, `updated_at`.
- `conversations/<id>.json`: `id` (equals the file name), `project_id`, `title`,
  `classification_effective`, `classification_source`, `model_id` (nullable), `created_at`,
  `updated_at`, `messages[]`.
  - message: `id`, `role` (`user`\|`assistant`\|`system`), `content`,
    `classification_effective`, `classification_source`, `created_at`, `status`
    (`complete`\|`partial`\|`error`\|`stopped`), and for assistant messages `provider`
    (`local`\|`company`), `model_id`, `prompt_tokens`, `completion_tokens`.
- `summaries/<conversation_id>.json`: `conversation_id` (equals the file name), `summaries[]`
  with `id`, `covers_until_message_id`, `content`, `classification_effective`,
  `classification_source`, `model_id`, `provider`, `created_at`.
- `models.json`: `models[]` with `catalogue_entry_id`, `name`, `artifact_digest`. References
  only: the importing machine fetches models from its own catalogue.
- `classification*`: `restricted` \| `internal` \| `public`; `classification_source`:
  `project` \| `import` \| `review`.
- Not included: commitment nonces, evidence, keys, provider settings, API keys, model files.

## 5 ZIP rules

Writers produce, and readers reject anything else (`P_ZIP`):
- Methods stored (0) or deflate (8) only; no encryption; no multi-disk; UTF-8 names (flag bit 11).
- Paths: relative, `/` separators, no `..`, no leading `/`, no drive letters, no backslashes, no
  control characters, unique after case folding.
- No directory entries; no symlinks or other special files. An entry whose external attributes
  state no file type (0, as many ZIP tools write) counts as a regular file.
- Limits: ≤ 100 000 entries; total uncompressed ≤ 2 GiB; per-entry compression ratio ≤ 100:1;
  sizes checked while inflating, not trusted from headers.
- Every known file present must be listed in `checksums.txt` (`P_UNLISTED`) and every listed
  known file must be present (`P_MISSING`); `project.json` and `checksums.txt` are required.
- **Unknown files** (any other safe relative name, e.g. `attachments/notes.md` from a later
  build) are not imported; the import succeeds with a warning naming each one.

## 6 Import rules

1. Validate the ZIP rules, then read `manifest.json` before any other entry. A `v` higher than the
   reader supports is refused with `P_VERSION` and the required version (the UI says which
   AIOS version is needed); a manifest that fails its schema is `P_FORMAT`.
2. Check `checksums.txt` against `checksums_sha256`, then each file against `checksums.txt`
   (`P_CHECKSUM`); validate each JSON file against its schema and canonical form (`P_FORMAT`).
3. Referential checks (`P_REFERENCE`): `project.id` = `manifest.project_id`; every
   conversation's `project_id` equals it; file names match ids; summaries belong to a
   conversation in the package; message and summary ids unique.
4. Import is all-or-nothing in one database transaction.
5. **IDs** are kept. Only when any of the package's ids already exists in this store are new ids
   assigned to all of them; the original id is then kept in the item's stored extension data
   (`original_id`) and the user is told. The original `project_id` and `package_id` are always
   stored as provenance.
6. Classifications are imported unchanged (never lowered); the project's
   `classification_source` becomes `import`, and the exported source is kept
   (`imported_classification_source`).
7. Record `project_imported` with `project_id`, `package_id` and `manifest_digest`.

Checksums detect damage, not tampering: v1 packages are not signed (P-3).

Error codes: `P_ZIP`, `P_FORMAT`, `P_VERSION`, `P_CHECKSUM`, `P_REFERENCE`, `P_UNLISTED`,
`P_MISSING`. The API reports `P_VERSION` as `p_version_<N>`.

## 7 Golden packages (J-01)

| File | Shows | Expected |
| --- | --- | --- |
| `current.aiosproj` | every file of the current layout, one summary, a model reference | imports |
| `older.aiosproj` | the minimum a first v1 build wrote (no summaries, no models.json, no optional fields) | imports with defaults |
| `unknown-file.aiosproj` | an extra file a later build could add | imports with a warning naming it |

`expected.json` lists the counts and warnings; `services/backend/tests/test_golden_packages.py`
imports each one on every change.

## 8 Decisions (to confirm at the freeze review)

- **P-1 Export of Restricted projects.** Allowed after an explicit confirmation that names the
  classification (the API refuses without `confirmed`); recorded as `project_exported`.
  Phase 1b policy gates may block it.
- **P-2 Encryption.** v1 packages are plain ZIP; the user chooses where to save. An encrypted
  package changes how bytes are read, so it would be Project Package v2, not an optional field.
- **P-3 Signature.** None in v1; integrity by checksums, provenance by the evidence event in the
  exporting store (`exporting_stream_id`, `export_event_id`). A detached signature can be added
  later as an optional file.
- **P-4 IDs on import.** Kept unless one collides; then all are renewed and the originals kept
  (section 6.5).
- **P-5 Commitment nonces.** Not exported, so a package cannot be used to open commitments in the
  source store's evidence log without the user's explicit evidence export.
