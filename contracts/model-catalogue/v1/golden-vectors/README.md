# Golden vectors: model-catalogue v1

Generated by `tools/contracts/gen_model_catalogue_vectors.py` (`--check` in CI); never edited by
hand. Each folder holds the exact bytes the backend receives (`catalogue.json`,
`catalogue.json.sig`) and `expected.json`: the pinned key, the last accepted `issued_at` and the
result (`accept` or the rejection code of section 6). The signing key is a fixed **test** key,
never a release key.

| Vector | Result |
| --- | --- |
| `valid` | accept |
| `altered-byte` | `C_SIG`: one byte changed after signing |
| `unknown-key` | `C_UNKNOWN_KEY`: signed by a key the build does not pin |
| `not-canonical` | `C_FORMAT`: valid signature over bytes that are not JCS |
| `wrong-version` | `C_FORMAT`: `catalogue_version` is not 1 |
| `rollback` | `C_ROLLBACK`: older than the last accepted catalogue |

The contract is frozen by ticket **I-01** (the `FROZEN` file in `../`). Once frozen, a change to
an existing vector is a semantic change and needs a new contract version and an ADR.
