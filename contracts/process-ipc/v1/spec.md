The key words MUST, MUST NOT and MAY are used as in RFC 2119. Every rule has an ID
(`IPC-nn`) and section 12 names the test that proves it.

## 1 Purpose

How the processes of one AIOS launch start each other, which process owns what, how the
per-launch secret and the secrets derived from it travel, how a process reports that it is
ready, and how every local request is authenticated. It is the basis of SR-08 / AC-10 / AC-11:
the launch token is generated in Electron main, travels only over a stdin pipe, and never
appears in argv, the environment, logs, renderer state or files.

## 2 Processes and ownership

| Process | Started by | Secret it receives | It serves | It owns |
| --- | --- | --- | --- | --- |
| Electron main | the user | — (generates `T`) | the window, IPC for the renderer | the launch token `T`, the update check |
| Renderer | Electron main | none | the UI | nothing secret |
| `backend.exe` | Electron main | `T` | local API (bearer `T`); gateway module (bearer `derive(T, gateway)`) | `chats.db` and its key (Credential Manager), the process manager and its Job Object |
| `evidence-writer.exe` | `backend.exe` | `derive(T, evidence-writer)` | writer API (bearer = that token) | `evidence.db`, the evidence signing key |
| `llama-server.exe` | `backend.exe` | `derive(T, engine)` | OpenAI-compatible engine (API key = that token) | nothing; it reads only the model file |

- **IPC-01** Exactly these five processes exist in v1. A process MUST NOT start a process this
  table does not list.
- **IPC-02** The local AI gateway is a module inside `backend.exe` with its own loopback
  endpoint. In Phase 1b it moves to its own process; its endpoint and its token purpose do not
  change.
- **IPC-03** Only the evidence writer opens `evidence.db` or holds the evidence signing key.
  The backend declares exactly one database (`chats.db`) and contains no code that names
  `evidence.db`. It reads evidence (timeline, exports with the signed manifest) only through
  the writer's API (open question 8: decided, see section 13).
- **IPC-04** Long-lived secrets (database key, evidence signing key, company API key) live
  only in the OS keystore and the wrapped Recovery Package. `keyring` is imported only by
  `aios_common.keystore`.

## 3 Launch token

- **IPC-10** Electron main generates `T` once per launch: 32 bytes from `crypto.randomBytes`,
  base64url without padding (`apps/desktop/src/main/backend/token.ts`). `T` is exactly 43
  characters of `[A-Za-z0-9_-]` and is held in memory only.
- **IPC-11** `T` and every token derived from it MUST NOT appear in command-line arguments,
  environment variables, log lines, files, crash output or renderer state. Only Electron main
  and `backend.exe` hold `T`.
- The backend uses `T` as its ASCII string bytes (it does not base64-decode it), both for
  bearer comparison and as the HMAC key in section 5.

## 4 Start-up handshake (parent → child, backend and evidence writer)

1. The parent spawns the child with its own stdin pipe and stdout pipe and no secret in argv
   or the environment. Electron main passes only `SystemRoot` and `LOCALAPPDATA` to the
   packaged backend.
2. **IPC-12** The parent writes **one frame** to the child's stdin and closes it: one JSON
   object (UTF-8), then a single LF, at most 4096 bytes, valid against
   `token-handshake.schema.json`: `{"token": "<T>", "api_port": 0}`.
   - `token`: required; 43 characters of base64url (launch token) or 64 lowercase hex
     (derived token).
   - `api_port`: optional, integer 0–65535, default 0. Electron main sends 0.
   - No other field is allowed.
3. **IPC-13** The child reads exactly one line (at most 4097 bytes), closes its stdin, and
   validates the frame. On any violation it writes one line ending in
   `handshake rejected: <reason>` to stderr (never the frame or any part of it), exits with **code 2**, opens no database and
   prints no READY line.
4. **IPC-14** With `api_port` 0 the child binds `127.0.0.1:0` itself and uses the port the OS
   assigns; otherwise it binds the given port. On Windows the socket is bound with
   `SO_EXCLUSIVEADDRUSE`. The child binds **before** it announces the port, so no other
   process can take the port in between.
5. **IPC-15** The child writes **one READY line** to stdout, and only once its server answers
   requests: the 6 bytes `READY `, a JSON object valid against `ready-line.schema.json`, LF.
   The backend's canonical form is `READY {"api_port": 50123}`.
6. **IPC-16** The parent reads stdout line by line, ignores lines that are not a valid READY
   line, uses the first valid one, and ignores later ones. It builds its client for
   `http://127.0.0.1:<api_port>`. The first request after READY is answered; no retry loop is
   needed.

The child MUST NOT write anything but the READY line to stdout. Diagnostics go to stderr or
to the content-free log files (SR-07).

### READY payload

| Field | Type | Req. | Meaning |
| --- | --- | --- | --- |
| `api_port` | integer 1–65535 | yes | Port of the local API (writer: of the writer API) on 127.0.0.1 |
| `gateway_port` | integer 1–65535 | no | Port of the gateway module (backend only, once G-01 ships) |

Readers ignore unknown fields (later versions add optional fields only).

## 5 Derived tokens

`derive(T, purpose) = lowercase_hex( HMAC-SHA256( key = ASCII(T), msg = UTF-8(purpose_string) ) )`

64 hex characters; implemented by `aios_common.handshake.derive`; vectors in
`golden-vectors/derive.json`.

| purpose | purpose_string | Received by | Presented by |
| --- | --- | --- | --- |
| gateway | `aios/ipc/v1/gateway` | gateway module (accepts it as bearer) | the backend's provider router |
| evidence-writer | `aios/ipc/v1/evidence-writer` | evidence writer (handshake frame) | backend → writer requests |
| engine | `aios/ipc/v1/engine` | llama-server (stdin, section 7) | gateway → engine requests |

- **IPC-20** Purpose strings are part of the frozen contract. A derived token cannot be turned
  back into `T` or into another purpose's token, so a leaked engine key opens only the engine.

## 6 Request authentication (backend, gateway, evidence writer)

Implemented once in `aios_common.asgi_auth.LoopbackTokenMiddleware`, before routing:

- **IPC-21** Every server binds `127.0.0.1` only (llama-server: `--host 127.0.0.1`).
- **IPC-22** Client address not in `{127.0.0.1, ::1}` → `403 {"error": "forbidden"}`.
- **IPC-23** Header `Authorization` must be exactly `Bearer <token>` (scheme case-sensitive,
  one space), compared in constant time (`hmac.compare_digest`) with the token that server
  accepts. Otherwise → `401 {"error": "unauthorized"}`. An unauthenticated caller learns
  nothing, not even which paths exist.
- **IPC-24** The shipped app (desktop profile) has no public paths and no `/docs` or
  `/openapi.json`. Public `/health` and `/docs` exist only in the developer profile, which
  `backend.exe` cannot select (the environment cannot change the profile).

## 7 Engine (llama-server)

- **IPC-30** The backend starts llama-server only when a local conversation needs it, with a
  free loopback port it chose and with `derive(T, engine)` as its API key. The key is written
  as **one line** (the 64 hex characters, then LF) to llama-server's stdin, which is then
  closed; llama-server reads it with the AIOS patch flag `--api-key-stdin`
  (`build/llama/patches/0001-api-key-stdin.patch`, D-03). `--api-key`, `--api-key-file`,
  `LLAMA_API_KEY` and any key file are forbidden. *(Replaces draft proposal P-1, which put the
  key in an environment variable; llama-server does not even read the variable it named.)*
- **IPC-31** Start-up flags are exactly
  `-m <model.gguf> --host 127.0.0.1 --port <port> --api-key-stdin --offline --no-webui
  --no-slots --no-ui-mcp-proxy`, plus model-sizing flags (`-c`, `-ngl`, threads). Flags that
  open files, tools, downloads, tunnels or extra endpoints (`--tools`, `--agent`,
  `--mcp-servers-*`, `--connect`, `--path`, `--media-path`, `--slot-save-path`,
  `--models-dir`, `--props`, `--metrics`, `-hf`) MUST NOT be passed. Reasons:
  `build/llama/README.md`.
- **IPC-32** The engine's environment is built from scratch, never copied from the backend:
  `SystemRoot`, `PATH` = the engine's own folder + `%SystemRoot%\System32`, and `TEMP`/`TMP` =
  a private folder under the data folder. No `APPDATA`, `PROGRAMDATA` or `LLAMA_*`
  variables: llama-server reads options from `LLAMA_ARG_*` variables and from `config.ini`
  under `%APPDATA%` and `%PROGRAMDATA%`. Reference: `minimal_env()` in
  `tests/engine/test_engine.py`.
- **IPC-33** llama-server prints no READY line. The backend polls the engine's `GET /health`
  until it answers 200 (503 = still loading) and reports the engine state in its own `/health`
  (`engine`: `not_started` → `starting` → `ok`, or `failed`). The renderer never sees the
  engine's port or key.
- **IPC-34** Question 12 — llama-server's `/health`. Upstream answers `GET /health` without a
  key (`{"status":"ok"}` or 503 while loading); every other route requires the key.
  **Decision: PENDING the technical reviewer.** Proposed: **A, accept** as a recorded,
  scoped exception to M-19's wording — loopback only, liveness only, no content and no model
  name, and the UI only ever sees the backend's `/health`. Alternative B: extend the patch so
  `/health` also requires the key (about 3 lines). The contract freezes with whichever is
  approved; `test_health_is_the_only_public_endpoint` pins A and changes under B.
- Engine output (stdout/stderr) is never written to the log files; the backend records only
  exit codes and its own content-free events (SR-07).

## 8 Evidence writer

- **IPC-40** The backend starts `evidence-writer.exe` at start-up (MVP 11.1) with the
  section 4 handshake and `token = derive(T, evidence-writer)`. The writer prints one READY
  line with its `api_port`.
- **IPC-41** The writer accepts only `Authorization: Bearer derive(T, evidence-writer)`
  through the same middleware (section 6), with no public paths. Only the backend can compute
  that token, so the writer refuses any other caller, including Electron main and the
  renderer.
- **IPC-42** (Question 8.) The writer's API serves every evidence operation: appending event
  intents with their input and output commitments, reading a project's timeline, and
  producing exports with the signed manifest. The backend never reads `evidence.db` itself.
  Endpoint shapes belong to the Evidence Wire Format and F-01, not to this contract.

## 9 Process lifetime

- **IPC-50** The **backend owns the Job Object**: it creates one Windows Job Object with
  `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` and assigns the evidence writer and every llama-server
  to it, so they die with the backend however the backend ends.
- **IPC-51** Electron main stops the backend when the app quits. The backend also exits when
  its parent process is gone, so a crashed Electron main cannot leave it running.
- **IPC-52** At start-up the backend ends llama-server processes left over from a crash
  (orphan clean-up, MVP 11.1 step 5). On close it stops the engine and the writer writes a
  shutdown checkpoint.
- **IPC-53** Every child gets its own stdin pipe, written and closed by its parent; handles
  are not inherited further (`close_fds`, the default on Windows). The backend closes its own
  stdin right after the handshake.

## 10 Renderer ↔ main

- **IPC-60** The renderer runs with `contextIsolation`, `sandbox`, `nodeIntegration: false`
  and the CSP in `apps/desktop/src/main/window.ts` (`connect-src 'none'`). It has no
  `fetch`, Node or `electron` (eslint, `packages/ts/config`). Its only door is `window.aios`.
- **IPC-61** The preload exposes exactly `@aios/bridge-contract` and registers no raw
  `ipcRenderer`. Main registers exactly the channels in `Channels` (v1: `aios:invoke`) and
  rejects unknown method names.
- **IPC-62** Main validates every call and every backend response with the bridge-contract
  zod schema, and never returns `T`, a derived token, a port or a backend error body to the
  renderer. Script running in the renderer cannot recover the token (AC-11).

## 11 Failure rules

| Condition | Required behaviour |
| --- | --- |
| Frame missing, not one JSON line, invalid against the schema, or larger than 4096 bytes | Child exits with code 2 before opening any database; prints no READY line (IPC-13) |
| READY not seen within 30 s | Main reports `backend_start_timeout` and kills the child |
| Child exits before READY | Main reports `backend_exit_<code>` |
| Second READY line, or any line that is not a valid READY line | Ignored by the parent |
| Engine `/health` not 200 within the engine start timeout | Backend kills it, reports `engine: failed`, falls back from Vulkan to CPU where allowed (FR-38) |
| A secret appears in argv, env, a log line, a file or the renderer | Contract violation (AC-10, AC-11) |

## 13 Decisions and deviations

| Item | Decision |
| --- | --- |
| P-1 engine token transport | **Replaced** by IPC-30 (stdin, `--api-key-stdin`, D-03). An environment variable is forbidden by M-19, and the variable named in the draft (`LLAMA_ARG_API_KEY`) is not read by llama-server, so the engine would have started without a key. |
| P-2 strict frame | Accepted: `additionalProperties: false` (IPC-12). |
| P-3 READY tolerance | Accepted: readers ignore unknown fields (section 4). |
| P-4 port choice | Accepted: Electron main sends `api_port: 0`; the child binds and reports (IPC-14). MVP 11.1 says main starts the backend "with a random port"; the OS-assigned port is random and avoids the pick-then-bind race, so this is a refinement, not a change. |
| P-5 child lifetime | Accepted and made exact: IPC-50 to IPC-52. |
| Question 8 | Decided (ticket D-02): the writer serves reads and exports over its channel (IPC-42). |
| Question 12 | Pending the reviewer (IPC-34); proposed A. |
| Exit code for a bad frame | 2 (IPC-13). |

## 14 Freezing

Frozen when all of these hold; then a `FROZEN` file is added next to this spec with the
date, the commit and the reviewer, and the status row above changes to *frozen*:

1. The technical reviewer has approved this spec, the D-03 patch and the question 12 choice
   (IPC-34 updated with the decision).
2. The golden vectors in `golden-vectors/` are generated and CI runs them against the Python
   and TypeScript implementations (`tools/contracts/gen_process_ipc_vectors.py --check`
   keeps them current).
3. `CLAUDE.md` links this contract.

After the freeze a rule's meaning never changes; new rules and optional fields go into a
later version with an ADR. "Pending" rows of section 12 are closed by their tickets without a
new version.
